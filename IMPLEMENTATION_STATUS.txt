ARCHITECTURE OVERVIEW
================================================================================

AUTHENTICATION FLOW:
1. User enters email, password, device_name in LoginPage
2. Form validates inputs (email format, password length, device_name required)
3. On submit: calls onLogin() from App.js → handleLogin()
4. handleLogin() calls authService.login(email, password, deviceName)
5. AuthService calls window.pos.auth.login({ email, password, device_name })
6. Preload.js bridges call to IPC main process
7. IpcHandler.handleLogin() calls ApiManager.login(email, password, device_name)
8. ApiManager sends POST /auth/login with credentials
9. Backend returns: { user: {...}, token, refreshToken, expiresIn }
10. Token stored via TokenManager.setAuthToken()
11. App state updated with user data
12. Router redirects to /dashboard

ERROR HANDLING:
- Validation errors caught by LoginPage component
- API errors caught by AuthService._extractErrorMessage()
- 8+ error patterns handled (validation, network, auth, timeout, etc.)
- User-friendly error messages displayed in LoginPage
- Errors cleared when user modifies fields

TOKEN MANAGEMENT:
- Tokens stored in OS keychain via TokenManager
- Stored in main process (secure)
- Retrieved automatically via request interceptor
- 401 responses trigger automatic refresh
- Tokens never logged to console
- Logout clears all token storage

SESSION RESTORATION:
- App.js calls authService.initialize() on mount
- AuthService checks for existing valid token
- If token exists and valid: session restored
- App shows /dashboard instead of login screen

BACKEND API EXPECTATIONS
================================================================================

Endpoint: POST /auth/login
Request Headers:
  Content-Type: application/json
  
Request Body:
  {
    "email": "user@example.com",
    "password": "password123",
    "device_name": "Terminal 1"
  }

Success Response (200):
  {
    "user": {
      "id": "user-id",
      "email": "user@example.com",
      "name": "User Name",
      "roles": ["pos-operator"]
    },
    "token": "eyJhbGc...",
    "refreshToken": "refresh_token_value",
    "expiresIn": 3600
  }

Error Response (400/401/422):
  Option 1 - Message field:
  {
    "message": "Invalid email or password"
  }
  
  Option 2 - Validation errors:
  {
    "errors": {
      "email": "Email is invalid",
      "password": "Password is too short"
    }
  }
  
  Option 3 - Errors array:
  {
    "errors": ["Email is invalid", "Password is too short"]
  }

All error formats are handled and displayed to user.
